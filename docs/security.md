# Security model

## Enforced controls

Service keys are randomly generated by the bootstrap utilities and only SHA-256 hashes are configured in the application. Comparison uses constant-time digest comparison. A credential binds one subject to one tenant and one role. Rotation is performed by adding a new hash, rolling instances, migrating clients, removing the old hash, and rolling again.

Role hierarchy is tenant-local: `public < employee < manager < admin`. `public` is not anonymous access. Every document search includes tenant equality and an allowed-role set. Deletes include tenant equality even for administrators. Document ingestion, deletion, tenant usage, and metrics require an admin credential. Feedback requires ownership of the usage request, including both tenant and subject.

Redis limits use hashed tenant/subject identities and an atomic expiry/counter script. Query embeddings are cached with tenant/model/query identity and a short TTL. Document text and answers are not cached there. Actual incoming body bytes are bounded even for chunked requests; JSON field sizes and document character limits add narrower constraints.

Application logs contain generated request identifiers, route templates, status, and duration. Questions, source text, credentials, and provider error bodies are omitted. The usage store contains source IDs and titles, which can still be sensitive. Application-generated logs can be clean while ingress, APM agents, debug tools, or hosting platforms capture sensitive data; configure those systems separately.

## Prompt and generation limits

The prompt labels sources and questions as untrusted data. A heuristic filter withholds excerpts containing selected suspicious patterns. This may produce false positives and does not catch every injection. Tenant/role predicates enforce authorization before a model sees any content.

Local Ollama generation sends authorized excerpts to the operator-configured model-server URL; keep that endpoint private and under your control.

Hosted generation is disabled by default and requires explicit data-egress consent, provider credentials, and numeric prices. When enabled, the question and retrieved authorized excerpts are sent to the hosted provider. Verify provider retention, region, contractual controls, and permitted data classes for your environment.

Citation labels in generated prose and a request to answer only from context do not prove grounding. Evaluate unsupported claims and citation accuracy using representative data. Local extractive mode quotes authorized source excerpts and does not synthesize a new answer.

## Deployment responsibilities

| Boundary | Required environment control |
| --- | --- |
| Client → API | TLS, private ingress or gateway, request/time limits, trusted proxy configuration, secret redaction. |
| API → storage | Private routes and firewalls/network policies; storage authentication and TLS where supported. |
| PostgreSQL | Least-privilege application identity, encrypted disks/backups, explicit retention policy, restore rehearsal. |
| Qdrant | Private endpoint, service credentials, encrypted storage/backups, protected snapshots and management APIs. |
| Redis | Private endpoint, ACLs/TLS as appropriate, explicit memory policy, credentials outside source control. |
| Model assets | Approved provenance, immutable revisions, offline/preseeded production cache, `trust_remote_code=False`. |
| Application secrets | Managed secret distribution, key rotation, no plaintext keys or provider secrets in Git. |
| Supply chain | Rebuild images for updates; scan runtime, optional model dependencies, base image, and pinned service images. |

The included Compose stack is for local development and does not configure storage TLS or Redis authentication. Restrict production dependency endpoints with your platform's native controls. The Kubernetes API resources require an environment-specific ingress and egress policy, not a permissive copy-paste policy that assumes service addresses.

## Isolation scope and open work

This is logical application isolation inside shared services. Storage operators retain cross-tenant access. Dedicated databases/collections/clusters and distinct encryption keys may be required for stronger physical boundaries.

End-user SSO/OIDC, per-user document ACLs, connector authorization propagation, signed ingestion provenance, an append-only administrator audit ledger, and automated retention/deletion jobs are not included. Rate limiting applies to the documented protected mutation/query routes; public health routes should be controlled at ingress. Metrics are service-wide and intentionally omit tenant labels.

Do not submit secrets or sensitive source documents in public issues. Report a suspected security issue privately to the repository owner; this repository does not currently publish a dedicated security contact address.
